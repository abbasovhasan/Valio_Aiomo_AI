# A4TB · Valio Aimo — current customer journey

Reviewed 14 November 2026, Europe/Helsinki. The C67 public release includes private accounts, Remember Me, saved preferences, candidate sorting/filtering and reviewable image/voice input. The production frontend build, **171 backend tests** and **47 extended deployed checks** passed. The hosted checks exercised scoped access/preferences, multi-product edits, budget/version failures, separate-manager approval, simulated confirmation/retry/receipt recovery, actual local OCR/ASR and live NVIDIA/Valio reads. Local browser checks covered registration, Remember Me, preferences and editable media previews. The owner separately confirmed correct public-site microphone/accent transcription; this is one user observation rather than a speech accuracy benchmark. Final browser coverage and source handoff are recorded in [ACCEPTANCE_RECORD.md](ACCEPTANCE_RECORD.md).

Open [A4TB · Valio Aimo](https://a4tb-valio-aimo.cozyhawthorn4.chatgpt.site). Smart order is the primary journey; Meal planner is an editable bolognese/lentil planning route. Trust scenarios uses the separate shared Aurora demonstration mandate. Every order is simulated.

| Stage and customer input | Real processing and visible output | State, authority and failure recovery |
|---|---|---|
| Choose shared or private access | **Demo access** accepts a buyer or approver code. **Create workspace** takes name, username, 12–128-character password and buyer invitation code; **Account sign-in** accepts username/password | `/session`, `/auth/register` and `/auth/login` assign role/customer/workspace on the server. A private registration creates synthetic buyer/customer IDs, not a supplier contract. Passwords use salted scrypt hashes; duplicate/wrong credentials and rate limits are explicit errors. |
| Decide whether to remember the device | **Remember me for 30 days on this device** chooses a persistent cookie/server expiry; unchecked uses a browser-session cookie and eight-hour server expiry | Session tokens are HttpOnly cookies; their hashes and revocation are persisted server-side. Browser session restoration can retain session cookies. **Sign out** explicitly revokes the session and removes the cookie. No password is put in local storage. |
| Recover the buyer's own workspace | The UI fetches `/session`, then the buyer-scoped remembered procurement session ID | Local storage contains a buyer-scoped pointer, not complete cart data. Server scope checks protect carts/preferences/receipts. Account changes remount the workbench and clear prior visible state; a missing/stale pointer cannot grant another customer's access. |
| Describe the request | Text is editable in the composer. POST `/procurement/sessions` interprets measured products, quantities/units, date, budget, preferences and unresolved specifications | Local parser or validated NVIDIA proposal supplies language interpretation. Deterministic code owns product evidence, arithmetic and authority. Original wording/requirements and ambiguities are persisted. Unknown requirements remain unresolved. Default balanced behavior allows comparison; cheapest is an explicit strategy. |
| Add speech or a list image | **Speak your order / Stop & transcribe**, **Upload audio**, or **Add photo or list** produces **Editable extracted text** and uncertainty messages | Buyer-authenticated `/input/audio` defaults to server-local Whisper base; `/input/image` defaults to server-local Tesseract English/Finnish printed OCR. Uploads are bounded to 5 MiB; audio is bounded to 30 seconds and images to supported JPEG/PNG size/dimensions. Corrupt/unsupported input is rejected. Microphone denial offers typing/upload alternatives. |
| Optionally choose cloud image reading | **Image reading & privacy** offers a separate NVIDIA vision reader | Nonconfidential-demo consent is required before cloud upload/extraction. The sanitized image can then be sent to the trial service. The local default does not send media to an external recognition provider. Server uploads are processed for extraction rather than stored as workspace attachments; selected text is saved only when submitted as a purchasing request. |
| Review and combine input | The customer corrects extracted text, selects **Add this text to my request**, and then explicitly builds or updates the cart | Extraction does not purchase or automatically create a cart. Product photos do not authorize invented quantities. Image/audio text and embedded instructions remain untrusted input; prices, stock, permissions and final quantities still require independent verification. |
| Set saved preferences | **Buying preferences** stores a soft priority, preferred brand/origin and organic preference using buyer-scoped GET/PUT `/preferences` | **Save preferences** and **Clear saved preferences** persist only the signed-in buyer's defaults. **Use saved preferences for this new request** controls new-session application. Explicit request instructions/hard requirements override defaults. Saving never rewrites an existing cart or grants spending authority. |
| Choose interpretation and commercial evidence | Price/stock source selects authored fixture or live Valio sandbox. The NVIDIA interpretation checkbox is independent and defaults off | NVIDIA trial use is an explicit opt-in for nonconfidential challenge/evaluation text; image consent is separate. These selections are fixed for the saved session. Fixture plus local parser avoids those provider calls; fixture plus NVIDIA still makes a model request. Supported recipe turns may use deterministic planning. Displayed provenance states the actual path. Provider failure never silently becomes a successful fixture. |
| Retrieve and inspect real candidates | Backend catalog discovery and bounded quotations produce actual candidate IDs, commercial facts, issues and match explanations | Hard suitability, source dimensions, lot increments, stock/date/freshness and commercial checks are deterministic. Related semantic/substitution candidates can require explicit choice. Rich Product evidence exposes supplied manufacturer/ingredients/allergens/storage/conversion sources and unknowns, not invented metadata. |
| Customize comparison | **Sort & filter products** sorts supplied subtotal/per-unit price, brand, origin or available date; filters declared attributes/brand/origin and compliant choices | Controls change the view only. Unknown is not an explicit match, unknown sort values come last, result counts/reset are visible, and the selected card stays pinned even outside filters. Four candidates appear initially; **Compare N more products** exposes the rest. The retrieved set is not the whole catalog. |
| Select or edit a product requirement | **Choose**, **Product search / Find products**, quantity **Update**, a follow-up message or the remove control submits versioned actions | Unaffected lines/selections persist. Query changes clear that line's old choice while keeping hard requirements. Shared SKU demands aggregate before pack rounding and stock validation. Server totals/surplus and eligible comparison deltas are displayed; the UI does not invent financial differences. |
| Resolve budget, availability or delivery conflicts | Cart **Apply requirements** changes explicit budget/date and re-quotes; product cards explain missing facts, shortage or unsuitable alternatives | The customer budget is hard; manager spend authority is separate. No automatic quantity reduction, diet relaxation, budget increase or delayed-delivery acceptance occurs. Incomplete carts cannot be confirmed. Shipping/service charges remain excluded from the quoted item subtotal. |
| Plan a supported meal | The bolognese example scales illustrative raw/dry ingredients with dietary allocations; missing overlap uses **Diners who need both diets / Apply overlap** | An explicit answer recalculates the saved recipe intent. Recipe acknowledgement is separate and cannot certify products or waive evidence gaps. The editable Meal planner retains detailed source/grams/cohorts. Unsupported dish breadth is not claimed. |
| Transfer a saved recipe | **Quote this shopping plan** posts saved plan ID, optional selections, source, delivery date and optional budget to `/procurement/sessions/from-meal-plan` | Saved quantities, recipe source and hard dietary/sourcing facts carry into Smart order. Exact candidates are checked against the saved plan. Shared products consolidate before rounding. Fresh recipe review and all hard checks are still required; JSON export remains a draft. |
| Review and obtain manager approval | **Review & confirm** is available only for an eligible basket. Above the authored threshold, a distinct manager reviews **Approve this exact cart** | For private accounts, **Approve this workspace** pre-fills the target workspace ID; the separate manager code grants scoped approver access. An ID or buyer code alone does not. Approval binds the exact unexpired basket; changing products/quantities/date/price requires new approval when still needed. |
| Confirm the simulation | The buyer selects **Confirm simulated order**; `/confirm` rechecks current commercial/catalog facts and atomically records scoped synthetic spend and one receipt | A persisted retry key prevents duplicate commitment. Concurrent/stale edits are rejected and current state reloaded. A confirmed cart is closed to edits. No supplier order, stock reservation, payment or invoice is created. |
| Inspect result and return later | **Your order, on the record.** shows immutable receipt items, exact package quantities, reference, requested date, item subtotal/source, approval and next steps | **Verify receipt** uses read-only `/verify`; it checks stored gateway consistency/basket binding, not a supplier signature or proof of delivery. Reload restores the same buyer's record. **New request** starts another draft without deleting receipts. |

A real purchase must use an authorized supplier channel and the customer's actual contract. Confirmation here schedules no supplier delivery. Private identities cannot run the shared Trust scenarios mandate; switching to the shared buyer code intentionally re-enters that separate demonstration. No journey step performs a final Junction submission.
