# A4TB · Valio Aimo customer journey

15 November2026. The current existing-SPA flow uses shared Product Details/comparison/Review order components and the existing scoped backend transaction path. [Current acceptance](SECURE_PURCHASING_ACCEPTANCE.md) distinguishes automated, real-browser and hosted evidence; [checking guide](WEBSITE_CHECK_GUIDE.txt) gives exact manual steps. All orders are simulated.

| Customer step | Interaction | Enforced result |
| --- | --- | --- |
| Enter a workspace | Sign in → controlled Buyer/Approver cards, or Use an account for password, invitation registration and code paths | Server-issued identity/scope; private carts/preferences/history are separate. Approve this workspace still requires the separately held assigned manager code. An ID alone grants nothing. |
| Return later | Optional Remember me for30days; otherwise browser-session cookie/eight-hour server expiry | Hashed persistent sessions, expiry and sign-out revocation. Browser lineage survives role changes to deny the creating actor's restricted decision. Shared credentials remain simulated actors rather than enterprise human identity. |
| Define the purchase | Type quantities/products, delivery and optional maximum budget once in the request header | Budget is a buying constraint, not authority/funds. Deterministic current policy, known dimensions, product evidence and current quotes decide eligibility. No model can grant permission. |
| Speak or read a list | Voice input, Upload image or Take a photo; inspect editable extracted text before Add to request | Local Whisper for voice; ordinary images automatically try NVIDIA and identify real local fallback when used. Nonconfidential demo images only. OriginalJPEG/PNG≤5MiB, browser resize≤1600px; server decompression guards remain. Media does not purchase or change a cart until text is added/submitted. |
| Save usual requirements | Buying preferences: mandatory dietary/exclusions and optional brand/origin/priority | Saved hard rules remain global even when optional defaults are off; current drafts revalidate. Clearing saved-only restrictions needs a fresh quote; explicit request restrictions remain. Missing evidence is not safety. |
| Discover products | Smart Order retrieves relevant bounded alternatives; Products browses/paginates the full supplied catalog with its own filters/sorts | Actual catalog identities; price/date page sorts apply only to quoted results. Unknown facts stay unknown/last. Provider failure never silently fabricates fixture prices. |
| Inspect one product | Subtle Product details action; desktop right drawer/mobile bottom sheet | Shared accessible modal, one detail scroll owner, exact supplied facts/sources, optional verified image. No inline card expansion, cart movement or selection/filter loss. |
| Compare options | Manual Compare checkboxes then Compare items for two/three; fourth asks Replace/Cancel | Same optional panel in Smart Order and Products, independent page lists/cart. Common-unit prices and same-request rounded cost where calculable; unlike units/missing facts remain explicit. Choosing remains explicit and revalidated. |
| Edit a basket | Choose, quantity Update, Find products, remove or conversational changes | Versioned actions preserve unaffected lines. Shared SKU demands combine before package/stock rounding. New material facts invalidate old approval. |
| Plan a meal | Edit dish/servings/ingredients/cohorts and recalculate | Illustrative recipe is unverified. Dirty requirements remove compliant selected presentation and disable transfer. Only currently suitable candidates can satisfy unchanged hard requirements. Missing/contradictory evidence/invalid conversion stays unresolved. |
| Transfer ingredients | Add ingredients to cart after explicit existing-cart handoff decision | Stored recipe quantities/restrictions/date/budget reach a separate draft. Fresh chef review and dietary/commercial checks remain. Nothing is ordered. |
| Review | Review order from ready, blocked or approval cart; Back to cart/Edit requirements preserves the editor | GET only: original request, buyer/workspace, quantities/packages, comparable price, item total/cost scope, delivery/diet facts, requested budget, trusted authority and exact excess. Detailed policy/audit is expandable. Review does not re-quote or submit. |
| Request an exception | Optional explanation then Request approval | Original budget is retained. Exact requested-budget and/or authority reasons, amount, version/fingerprint/explanation persist and reach the eligible manager queue. Hard organizational/product blockers offer editing rather than financial bypass. |
| Manager reviews | Separate authorized browser/profile → Approvals → Review request | Complete read-only basket, reasons, budget/authority/allowance/explanation/submission time/history. Optional comparison uses the quoted snapshot and cannot change it or refresh prices. Same originating actor/principal cannot decide its own request after role switching. |
| Manager decides | Approve exact basket; Decline basket; Request changes with a note | Current decision scope, assignment and permissions are required; approval additionally requires its ceiling and exact unexpired valid snapshot. Approval grants no future budget/authority and creates no order. Reject/changes require fresh buyer revision/request; authorized recovery remains available when current hard blockers prevent approval. |
| Buyer submits explicitly | Refresh status → Approved → Confirm simulated order | Fresh commercial/catalog/constraint/authority/approval/version checks, checkout lock and atomic cumulative committed spending. Idempotent retry returns the original receipt. No supplier order, reservation, invoice or payment occurs. |
| Inspect or cancel | Verify receipt/reload; History open/reuse/archive/personal removal; Cancel request on an unsubmitted draft | Verification checks gateway-held record consistency/scope, not supplier signature/delivery. Reuse is a fresh draft. Hiding personal history does not erase purchasing evidence/spend. Cancelled drafts cannot submit stale references. |

The configured lifetime per-workspace simulated allowance is separate from a per-order authority threshold; pending approvals reserve no financial funds or stock. Current hard limits remain after financial approval. Two competing approved baskets can therefore be refused at final submission when another has consumed allowance. No verified bank balance, supplier credit facility or payment terms are asserted. Real purchases require the authorized supplier channel/customer contract. There is no final Junction submission step.
